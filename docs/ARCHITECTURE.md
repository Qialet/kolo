# Архитектура Kolo

## Потоки данных
- Сервер (apps/api) владеет живой симуляцией: SimulationService строит город из файла района (env DISTRICT_FILE или data/districts/belgrade-center.json выше cwd) и крутит шаг 50 мс.
- Каждые 100 мс шлюз LiveGateway рассылает кадр (позиции машин, фазы светофоров, часы симуляции clock) в namespace socket.io «/live»; биты flags машины описаны в contracts/live (4 и 5 — левый и правый поворотник, 6 — в тоннеле); последнее поле — высота позы над улицей (настил моста, шаг 0,01 м).
- Раз в секунду рассылается KPI; бизнес-события (заказы, поломки, смены статусов) идут сразу как события ленты и обновления заказов.
- Клиент (apps/web) строит тот же город локально из того же файла района, поэтому по сети ходят только динамические данные.
- При подключении сервер шлёт hello (id и версия района); при расхождении с версией вкладки клиент предлагает перезагрузку.
- Детали выбранного объекта (маршрут такси, светофор, автобус) клиент опрашивает по REST раз в секунду через TanStack Query; остановку — раз в 5 с, линию — раз в 10 с.

## Данные реального города
- Сырьё (выгрузка Overpass, GTFS data.gov.rs) лежит в data/raw вне git; скачивание — только с разрешения пользователя.
- Импорт: packages/sim/src/import (подпуть @kolo/sim/import, в веб не попадает), CLI packages/sim/scripts/import-district.mjs после сборки sim пишет data/districts/belgrade-center.json.
- Файл района: meta (опорная точка, рамка, дата снимка OSM, версия GTFS, хэш версии FNV-1a), roads (узлы, рёбра с полосами и тегами, запреты поворотов, размеченные пешеходные переходы, декоративные рельсы: депо, запасные, железная дорога; paths — только рисуемые мощёные пути: улицы вне графа, service, пешеходные улицы, дорожки) и transit (календарь, остановки, линии, варианты с shape, профили времён и отправления по сервисам); типы — packages/sim/src/city/district.ts.
- Файл района также несёт здания, площади, деревья, адреса, POI (у площадных — контур) и площадки депо (импорт osm-places.ts, список депо DEPOT_SITES).
- buildCityFromDistrict превращает файл в City (граф, места, дворы депо) примерно за 0,3 с.
- Web: scripts/sync-districts.mjs перед dev и build копирует файлы в public/districts/<id>.<version>.json и пишет manifest.json (папка вне git); lib/city грузит manifest без кэша, файл — из кэша браузера.

## Персистентность
- PostgreSQL через Prisma 8 (contract-first). Источник схемы — apps/api/src/prisma/contract.prisma.
- В БД: партнёры, парки, водители, машины, журнал смен статусов, заказы, события заказов, возражения.
- В памяти: позиции, полосы, фазы светофоров, активные заказы. Хуки симуляции пишут в БД через последовательную очередь, чтобы событие не опередило строку заказа.
- При старте незавершённые заказы прошлого запуска закрываются со статусом «Перезапуск системы»; нумерация кодов продолжается с максимума в БД.
- Пустая БД заполняется автоматически при старте (SeedService), отдельный сид-скрипт не нужен.
- Сид дополняет флот до 60 машин (24/18/18) без дублей номеров; при каждом старте адрес, координаты ворот (Park.x, Park.z), вместимость и боксы парков сверяются с двором района.
- Миграция belgrade_parks: колонки Park.x и Park.z и удаление заказов процедурного города (события и возражения — каскадом).

## Prisma 8 — как работать
- После правки контракта: в apps/api выполнить prisma contract emit (обновит contract.json и contract.d.ts, их коммитим).
- Миграции: prisma migration plan с именем, затем prisma db migrate. Папка apps/api/migrations под git.
- Запросы только через db.orm.public.Модель — см. скил prisma-8 в apps/api/.claude/skills.
- Даты хранятся как TimestamptzString (строки), на клиент отдаются в ISO через common/time.

## Модули API (NestJS 12, ESM)
- DatabaseModule (глобальный): DatabaseService с единственным клиентом Prisma и SeedService.
- SimulationModule: SimulationService, LiveGateway, SimulationController (/api/sim: состояние, управление и синхронизация часов, детали такси, автобусов, остановок, линий и светофоров, режим светофора).
- FleetModule: /api/fleet/parks, /api/fleet/vehicles, смена статуса машины, история статусов.
- OrdersModule: /api/orders (список, деталь с событиями и возражениями, создание, отмена, ручное назначение, возражения и их решение).
- Валидация тела и query — zod-схемы из packages/contracts через ZodPipe.

## Фронтенд (Next.js 16)
- Одна страница: LiveConsole — полноэкранный Canvas и плавающие панели.
- Консоль рендерится после загрузки города (иначе «Строим Белград…»); Canvas грузится через next/dynamic без SSR. Сцена: земля и площади, асфальт (ленты city.roads и площадки узлов city.pads), здания по чанкам, светофоры, машины, оверлеи, проектор меток.
- Здания — экструзия контуров, слитая в меш на чанк (по центроиду контура); выбор — по индексу треугольника внутри чанка; выделение — контур здания.
- LOD (lib/lod): уровень near от зума 2,6, far ниже 2,2, между — прежний; уровень в ui-store, его ставит CameraRig. Деревья и припаркованные — instanced-меш на чанк 400 м (scene/chunked), three отсекает чанки в основном проходе и в проходе тени.
- На far: простые боксы вместо скруглённых, без колёс, фонарей и пантографов, машины и деревья без теней, стены без окон, грубые лампы светофоров, подписи POI от веса 3. Машины вне кадра в instanced-меши не пишутся (позы для оверлеев остаются).
- Тень — квадрат вокруг цели камеры по размеру вида (200–1400 м); PerformanceMonitor drei снижает dpr до 1 при падении кадра. Остановки — 4 instanced-меша на все.
- Подписи над 3D — обычный DOM-слой (SceneLabels и WorldLabel), позиции проецирует LabelProjector раз в кадр. drei Html не используется: в dev он ломает рендер.
- Машины — instanced-меши; интерполяция кадров в FrameBuffer (lib/live) с задержкой 140 мс; позы делятся через livePoses.
- Трамваи: в кадре только передняя точка; lib/tram-trail хранит след каждого трамвая (точка через 0,5 м, длина плюс 5 м, при скачке больше 20 м — заново по heading) и отдаёт позы секций; в livePoses у трамвая — середина вагона.
- Мосты — buildDeckGeometry: поднятые ленты, площадки и плиты трамвайной эстакады отдельным мешем с тенью (борта, парапеты, опоры); разметка, рельсы, провода, платформа Mostar, знаки и светофоры — на высоте настила; порталы тоннеля — buildPortalGeometry. Машины и секции трамваев (по следу с высотой) стоят на y кадра и наклоняются по разнице высот кадров; машина с битом тоннеля не рисуется и не попадает в livePoses (нет кольца и подписи).
- Пути, балласт и платформы — buildTrackGeometry (scene/city-geometry) по рельсовым полосам, коннекторам и декоративным путям City (tracks с scenery); балласт — где ось пути вне асфальта (roadSurface); провода троллейбусов и трамваев — одна геометрия линий.
- Пути City.paths (отбор в import/osm-paths: без тоннелей, крытых, площадей, тротуаров и footway вдоль улиц) — лентой со скруглениями: service и улицы вне графа асфальтом в buildRoadGeometry чуть ниже улиц, пешеходные улицы и дорожки плиткой в buildGroundGeometry над покрытием земли.
- Состояние UI — zustand (lib/ui-store), живые данные — zustand (lib/live), серверные данные — TanStack Query (lib/queries); часы Белграда и тип дня — lib/belgrade из кадра.
- Включён React Compiler: не обращаться к ref в render, не мутировать значения хуков (камеру брать из state в useFrame). Проверка — pnpm lint.

## Запуск и порты
- pnpm dev в корне: turbo собирает пакеты, запускает tsc watch пакетов, раннер API (apps/api/scripts/dev.mjs) и next dev (порт 3000).
- Раннер API: tsc watch плюс перезапуск сервера (порт 4000) с дебаунсом при изменении dist API, packages/sim или packages/contracts.
- Переменные: apps/api/.env (DATABASE_URL, PORT, WEB_ORIGIN), фронт — NEXT_PUBLIC_API_URL (по умолчанию localhost:4000/api).

## Тесты
- packages/sim: импорт (OSM и GTFS) и полигоны, календарь и праздники, граф района, адреса, POI, депо и остановки, сеть вариантов, расписание транспорта, светофоры, 15-минутный прогон симуляции и 10 минут фонового трафика, сервисный цикл такси.
- apps/api: unit (ZodPipe, даты, поиск файла района) и e2e (health, парки с координатами, версия района, остановка и линия, трамвайная линия и отправления общей остановки, синхронизация) — e2e требует локальный Postgres.
- apps/web: чистые модули без импортов (lib/tram-trail, lib/search, lib/lod) — встроенным node:test Node 25 (файлы *.test.mjs, импорт .ts напрямую); vitest в web не ставится.
- Визуальная проверка: скриншоты через playwright-core и системный Chrome; в dev доступны window.__koloUi, window.__koloFrames и window.__koloGl (состояние R3F).
- Аудит дорог: node scripts/road-audit.mjs в packages/sim после сборки — счётчики дефектов с худшими местами (lowDecks — настил ниже 5 м над нижней полосой); --map имя:x:z:размер[:пикс/м] рисует карту дорог сверху в tmp/road-maps.
- Бюджет кадра: pnpm perf в apps/web при запущенном dev — draw call и треугольники за кадр на видах overview, home, near и шаг сервера; --budget сверяет с бюджетом (overview 900 тыс. и 260, home 1,2 млн и 150, near 900 тыс. и 120), --cpu N замедляет CPU.
