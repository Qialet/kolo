# Дизайн: реальный Белград вместо процедурного города

## Зачем
- Kolo должен показывать узнаваемый Белград: реальные улицы, здания, площади, светофоры и кольца, а не «город в духе Врачара».
- Общественный транспорт ходит по настоящему расписанию GTFS: едет до остановки, стоит, едет дальше и старается попасть в плановое время.
- Механика такси, заказов, парков и админ-рычагов остаётся прежней, меняется только мир под ней.

## Цели
- Район около 5 км² на правом берегу Савы, собранный офлайн из OSM и GTFS в один версионируемый файл.
- Сервер и клиент строят мир из этого файла (seed больше не источник города).
- Общий дорожный граф: полилинии, перекрёстки любой степени и углов, многополосность, кольца, светофоры из OSM.
- Автобусы, троллейбусы, минибусы, затем трамваи — по расписанию на реальном времени Europe/Belgrade.
- LOD и отсечение, чтобы район держал плавный кадр.
- Закладка на расширение: соседние районы добавляются без сдвига координат существующих объектов.

## Не цели
- Левый берег Савы (Новый Белград, Земун) и север за Дунаем (Борча, Крњача) — не берём.
- Реальное время транспорта (GPS) и любые неофициальные API — нет.
- Зависимость трафика и спроса от времени суток (отдельная фича «день и ночь») и пешеходы (бэклог).

## Анти-цели (провал, даже если «работает»)
- Любые сетевые запросы к OSM, GTFS или картам в рантайме.
- Скачивание данных или установка пакетов без явного разрешения пользователя: каждый раз спросить и ждать ответа (что, откуда, размер, зачем).
- Машины, проходящие сквозь друг друга, дедлоки на реальных перекрёстках, автобусы мимо остановок.

## Решения пользователя
- Площадь около 5 км², только правый берег Савы; в будущем город расширяется.
- LOD делаем.
- Транспорт ведёт себя как сейчас: едет к остановке, стоит, едет дальше, попадая в расписание.
- Часы симуляции — реальное белградское время (ночью рейсов мало).
- Ускорение остаётся: при нём часы уходят вперёд; после возврата к ×1 есть кнопка «синхронизировать», возвращающая реальное время и пересобирающая транспорт по расписанию; такси и заказы не трогаются.
- Объём — этапы «Белград 0–5» роадмапа плюс то, что здесь согласовано.

## Источники данных (найдены, ничего не скачано)
- GTFS: data.gov.rs, датасет «Градски јавни превоз у Београду (GTFS)», издатель — Градска управа града Београда; файл bgprev-belgrade-rs.zip, 16,8 МБ, изменён 31.10.2025; трамваи, троллейбусы, автобусы, минибусы; лицензия — Serbian Open Data License (атрибуция). Пригородный фид «Beograd Prigrad» не нужен.
- На карте атрибуция «© OpenStreetMap contributors» (ODbL) и источник GTFS (data.gov.rs).
- OSM: предпочтительно выгрузка Overpass по рамке района (JSON, десятки МБ, без новых зависимостей); альтернатива — Geofabrik Serbia PBF (сотни МБ и нужен парсер PBF). Перед скачиванием — разрешение.
- Распаковка zip — системным tar Windows, без новых пакетов; если не хватит — спросить про библиотеку.
- В OSM правого берега маршруты транспорта размечены по PTv2 и сверены с GTFS — годятся для сверки трасс.

## Рамка района (моё решение, сдвигаемо)
- Примерно 1,9 × 2,8 км: север — Калемегдан и Студентски трг; юг — Храм Светог Саве; запад — набережная Савы и Савамала до Бранкова моста; восток — Скупштина и Ташмајдан.
- Внутри: Кнез Михаилова (пешеходная), Теразије, Трг Републике, Кральа Милана, Кральа Александра, кольцо Славии, Главна железничка, Београдски сајам, Калемегдан. Аутокоманда не входит — вторая кольцевая ждёт расширения.

## Координаты и расширяемость (моё решение)
- Фиксированная опорная точка проекции — центр кольца Славии (координаты из OSM), локальная проекция в метры: x — восток, z — юг.
- Опорная точка не зависит от рамки: новый район — новый файл района в той же системе координат, мир собирается из списка районов.
- Ребро рамки: улицы обрезаются по границе, на обрезанных концах — источники и стоки фонового трафика и транспорта; заказы и поездки такси — только внутри рамки.
- Рельеф не моделируется, мир плоский (моё решение); мосты и тоннели (Теразијски тунел) пересекают улицы без перекрёстка, машины в тоннеле скрыты. Настилы мостов в сцене подняты над улицами с пандусами (решение пользователя, план 10.7).

## Пайплайн импорта (моё решение)
- Отдельный офлайн-инструмент в монорепо читает сырые OSM и GTFS из неотслеживаемой папки и пишет компактный файл района в git (цель — несколько МБ в сжатом виде).
- Импорт делает тяжёлую чистку: обрезка, склейка путей, топология перекрёстков, упрощение полигонов, адреса, остановки, обрезка GTFS по рамке.
- Геометрию полос, коннекторов и конфликтов выводит packages/sim из файла детерминированно на сервере и клиенте.
- Файл несёт версию (хэш); сервер сообщает её при подключении, клиент при расхождении предлагает перезагрузку.
- Клиент получает файл как статический ассет web, а не из API.
- Процедурный генератор удаляется; тесты движка идут на малом вырезе реального района и на полном районе (моё решение).

## Дорожный граф и движение
- Улицы из highway (без service, footway, pedestrian): класс, lanes, oneway, ширина, maxspeed; полосы — полилинии.
- Перекрёсток — только общий узел OSM путей на одном уровне (layer); перекрёстки любой степени: коннекторы по допустимым поворотам (turn:lanes и restrictions, иначе эвристика), конфликты заранее.
- Светофоры по highway=traffic_signals, близкие узлы одного перекрёстка группируются; фазы по группам подходов, сербская последовательность сохраняется; нерегулируемые — по приоритету класса дороги.
- Кольца (junction=roundabout): въезд с уступкой кольцу.
- Перестроения внутри сегмента, IDM, ограничение скорости на кривых.
- Режимы админа для светофоров сохраняются (авто, мигающий жёлтый, удержание зелёного по направлению).

## Здания и застройка
- Контуры зданий, высота из height или building:levels, иначе по типу; экструзия, окна шейдером по высоте этажа; стиль и палитра — как в DESIGN.
- Парки, площади, зелень, Сава из landuse, leisure, natural; Калемегдан — парк с крепостью.
- Адреса из addr:*, точка подачи у ближайшего бордюра нужной стороны.
- POI: вокзал, ТЦ, больницы, университеты, рынки, отели — точки притяжения и веса спроса.
- Деревья, дворовый декор, припаркованные машины — процедурно поверх реальных кварталов.

## Общественный транспорт
- Остановки из GTFS stops (латиница), привязка к полосе своего направления; карманы из OSM или эвристика.
- Трассы рейсов — GTFS shapes, сопоставленные с дорожным графом; сверка с OSM PTv2.
- Рейс, идущий через край рамки, появляется на границе в расчётное по расписанию время и исчезает при выезде.
- Стоянка на остановке 15–30 с (моё предположение); ранний приход — ждёт до времени отправления; опоздание — едет без ожидания, отклонение видно в UI.
- Календарь GTFS по дню недели и calendar_dates; если фид устарел, падать на ближайший подходящий шаблон дня.
- Троллейбусы — как автобусы, на рендере штанги и контактная сеть над их улицами; минибусы — способ опознать их в фиде выяснить на этапе 0.
- Трамваи — отдельным этапом после автобусов: пути из railway=tram, свои остановки, подчинение светофорам перекрёстков.
- UI: инспектор линии (остановки по порядку, интервал, следующий рейс), инспектор остановки (ближайшие отправления), пометка «по расписанию» или «опаздывает на N мин».

## Домен
- Партнёры прежние и вымышленные; депо — на реальных дворах и стоянках района, вместимость из геометрии.
- Число такси и фоновых машин масштабируется под площадь в пределах бюджета (моё решение).
- Спрос по весам POI, остановок и плотности застройки.
- Миграция БД: координаты парков; заказы процедурного города удаляются (демо-данные).

## Производительность
- Сервер: шаг симуляции укладывается в треть тика.
- Клиент: здания слиты по чанкам, два уровня LOD, отсечение чанков по камере; дальние машины — упрощённые меши; плавный кадр на обычном ноутбуке.
- Кадр WebSocket не должен расти линейно без предела: при необходимости компактный формат.

## Оставлено исполнителю

- Формат файла района, сжатие, структура инструмента импорта.
- Алгоритмы сопоставления shapes с графом, группировки светофоров, эвристик поворотов.
- Числа агентов, пороги LOD, размер чанков.
